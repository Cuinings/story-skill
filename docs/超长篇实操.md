# 超长篇实操：世界状态、滚动计划与历史修订

本页给 Codex 操作的可复查步骤，作者只需表达创作要求。它使用 schema 2；不要求现有书一次性补齐全部人物史，也不把模拟的第30→300章间隔当成已写完270章。

## 1. 在独立书目录开始

下面命令中的 `<tool>` 是当前安装技能的 `scripts/story.py` 绝对路径，`<书目录>` 是用户授权的唯一书目录，R 每次取最新 status/写入回执，不能连续硬编码同一个数值。JSON 必须 UTF-8 保存，Windows PowerShell 重定向的默认编码可能不同，建议由文件工具明确写 UTF-8。

```text
python "<tool>" init --book "<书目录>" --title "本书题名" --kind long
python "<tool>" status --book "<书目录>"
python "<tool>" template world
python "<tool>" template plan
```

先保存简短创作约定，包括授权范围、视角、字数口径、不可突破项，以及故事时间刻度。下面仅演示字段，不代表用户书中的既成剧情。将 `world-base.json` 写成：

```json
{
  "entities": [
    {"id":"jiang","name":"江棠","kind":"character","description":"正在整理交接记录"},
    {"id":"du","name":"杜承安","kind":"character","description":"参与交接的旧渡工"},
    {"id":"north","name":"北库","kind":"place","description":"本次核对地点"}
  ],
  "aliases": [{"alias":"小江","entity":"jiang","scope":"north-line"}],
  "facts": [{
    "id":"key-proposition","subject":"north","predicate":"钥匙可能的位置","value":"夹层",
    "clock":"main","start":0,"end":null,"hard":false,
    "evidence":{"kind":"author_plan","note":"作者准备让角色讨论的猜测；尚未证实"}
  }]
}
```

```text
python "<tool>" world-save --book "<书目录>" --input "<world-base.json>" --expect R
```

`author_plan` 资料在 context 的 planned 下，不能作为已发生事实。稳定 ID 才是身份；若两人都叫“老邱”，分别建 ID，按故事线建别名。跨线同时需要两人时直接用 ID，不能凭称呼猜测。

## 2. 卷、情节段和场景范围

按需取小模板，不读整个内部模块：

```text
python "<tool>" template world-volumes
python "<tool>" template world-arcs
python "<tool>" template world-lines
```

卷和段保存目标、进入/结束条件及代价；arc 引用 volume。同 ID 的作者计划可以滚动修订，正文已发生事件只能新增记录或走历史修订。不要提前细化几千章。

现有 plan 保留 goal、beats、constraints、stop、requires、length 等字段，额外按本章实际需要加入：

```json
{
  "volume":"v1",
  "arc":"a1",
  "line":"north-line",
  "entities":["jiang","du","north"],
  "time":{"clock":"main","start":20,"end":25}
}
```

这些是合并到完整 plan 的字段，不是可单独提交的完整章计划。`requires` 仍引用原有 notes 卡；`entities` 引用世界实体，两者不能混用。

```text
python "<tool>" plan --book "<书目录>" --chapter N --input "<完整计划.json>" --expect R
python "<tool>" context --book "<书目录>" --chapter N --budget-bytes 16000
python "<tool>" world-check --book "<书目录>" --chapter N
```

先查看 packet 的本条线断点、人物认知和证据。若北线停在第80章问话中，南线写到第90章，下一章回北线应带第80章的未完问题；不能把第90章另一场景的结尾当作北线现场。time 的两个端点若未知填 null，补证据前不做确定的赶路/冷却判断。不同 clock 之间目前没有自动换算。

## 3. 把已发生的变化随章提交

先真正写稿并审查，再执行：

```text
python "<tool>" lint --book "<书目录>" --chapter N --draft "<草稿.md>"
python "<tool>" prepare --book "<书目录>" --chapter N --draft "<草稿.md>"
```

把 prepare.delta 保存为输入，填写真实摘要、卡片变化、四项审查及问题处理。需要领域变化时增加 `world_changes`。以下形状说明“甲相信某命题，乙明确不知”，证据里的章号/完整哈希/原句必须取这次真实稿件；示例字符串不能直接提交：

```json
{
  "world_changes": {
    "knowledge": [
      {"id":"jiang-belief-1","actor":"jiang","fact":"key-proposition","state":"believes","clock":"main","at":20,"channel":"听到转述后暂时相信","evidence":{"kind":"chapter","chapter":1,"sha256":"完整稿件SHA256","quote":"稿件中支持江棠形成这一相信的原句"}},
      {"id":"du-unknown-1","actor":"du","fact":"key-proposition","state":"unknown","clock":"main","at":20,"channel":"承认没有见过夹层","evidence":{"kind":"chapter","chapter":1,"sha256":"完整稿件SHA256","quote":"稿件中杜承安明确不知的原句"}}
    ],
    "lines": [{"id":"north-after-1","line":"north-line","clock":"main","at":25,"place":"north","summary":"两人对钥匙去处没有达成确认","unfinished":"等待持有者到场核验","entities":["jiang","du"],"evidence":{"kind":"chapter","chapter":1,"sha256":"完整稿件SHA256","quote":"稿件中的具体未完动作"}}]
  }
}
```

```text
python "<tool>" commit --book "<书目录>" --chapter N --draft "<草稿.md>" --input "<审查后的delta.json>"
```

正文与 world_changes 在同一事务落盘；失败不能留下“正文有了、知识却没更新”的半次提交。确认 exports_complete 后才能交付。下一章不得把 author_plan 当作角色已知；没有认知记录只能说资料缺失，不能补造明确不知。

## 4. 伏笔、规则、资金及人物变化

```text
python "<tool>" template world-hooks
python "<tool>" template world-rules
python "<tool>" template world-uses
python "<tool>" template world-transfers
python "<tool>" template world-arc_steps
```

模板只返回单类字段，先确保引用的实体、命题和卷段已存在。未来准备写的使用/转移以 author_plan 保存，用 world-check 核对；写成后在 delta.world_changes 中把该计划 ID 转为真实正文证据，避免同一事件保留一份计划、一份实绩导致重复预测。

- 伏笔的每次变化有独立 id，但共用 hook；通过实体或故事线唤回原始铺垫，跨数百章也不靠关键词碰运气。window 是作者排期，hard_deadline 是角色说出的故事内期限。逾期只提示必须审查后果，角色可有意违约；真实违约记 breached＋reason，不记 fulfilled。fulfilled/breached 必须有正文证据。
- 规则按 rule＋version 保存，不靠覆盖旧描述解释升级。cooldown 是同 clock 的整数刻度；使用记录有 actor、rule、at。只有明确数据才产生冷却阻断；未知前置条件仍需读稿。exception 用于具体、已授权的例外，不能统一填“剧情需要”。
- 精确量用十进制字符串，例如 `"100000"`，单位放在资源定义与 quantity_text。`"十万"` 不能放在 amount；`约三成` 用 amount:null，不能用浮点假装精确。起始余额要 opening:true 及正文证据，普通收入不证明此前余额为零。
- arc_steps 保存欲望、策略、选择、代价、关系与结果。相同 pattern 重复只返回带例子的建议；刻意呼应、反复失败和安静场景仍由真实审稿判断。

## 5. 历史修订的候选分支

先读 `history-start --help`、`history-update --help`。正常章的 delta 可直接包含 `dependencies:[{"kind":"world.facts","ref":"事实ID","sha":"该依赖的真实SHA256"}]` 和 `dependency_review:{"complete":false,"note":"实际检查范围与剩余疑点"}`，随章保存；已有章可再用 `history-deps` 更新声明。可用的依赖包括 chapter/card/entity/rule/world.facts 等，实体定义的哈希不能代替人物具体认知/事实的哈希。complete=true 需要充分复核并包含 plan.requires 卡，不传时保守为 false。只有 ID 或关键词命中不等于语义依赖完整。

```text
python "<tool>" history-snapshot --book "<书目录>" --label "卷末" --expect R
python "<tool>" history-state --book "<书目录>" --chapter N --before --offset 0 --limit 50
python "<tool>" history-start --book "<书目录>" --chapter N --label "修正钥匙交付" --expect R
python "<tool>" history-inspect --book "<书目录>" --branch "返回的分支ID"
python "<tool>" history-inspect --book "<书目录>" --branch "返回的分支ID" --chapter N
```

检查返回的受影响章、必须决定的旧卡片、world_review_required 和审查模板。带 --chapter N 的 inspection 返回 base/candidate 正文及 chapter_review_template，note/quote 留空，不自动通过。普通 inspection 的 state_review_template 含精确 id、before_sha、before；after 不预填，须明确给完整卡片以保持/修改或 null 删除，并填候选 chapter、quote、note。默认50卡，用 --state-offset/--state-limit 续取，单页最多200，不自行猜卡片规范化后的哈希。不能只改第N章而跳过仍依赖旧事实的后文。原版此时继续有效，新的正文、摘要、依赖及审查放在候选分支中。

history-start/update/refresh/inspect 的 affected、world、hints 共用 --limit，默认25、最大200；state 独立使用 --state-limit，默认50、最大200。start/update/refresh 返回首批，继续阅读用 inspect 的 --affected-offset、--world-offset、--hints-offset、--state-offset。每段在 pages 中给 offset、limit、total、next_offset、complete，按各自 next_offset 续取，直到 null；不必让四段同步翻页。

```text
python "<tool>" history-inspect --book "<书目录>" --branch "分支ID" --affected-offset 25 --world-offset 0 --hints-offset 0 --state-offset 0 --limit 25 --state-limit 50 --budget-bytes 64000
```

上面的25只演示第二页位置，实际使用回执的 next_offset。complete 的含义是“本次响应包含这一段全部内容”；末页若 offset 非零，complete 仍为 false，不表示还存在下一页。affected 被分页时，review_template.reviewed_chapters 是 null，review_scope.chapter_ids_page 只是当前页。必须收齐同一 revision/manifest_sha256 下全部受影响章、状态和证据，再逐项完成审查并填写完整 reviewed_chapters，不能复制当前页就声明全范围覆盖。

这四个分支命令及 history-state、cache-get 的 --budget-bytes 默认64000，按 UTF-8 字节而非 tokens 计。--chapter 的完整正文对照也受总预算限制；超限报 budget_exceeded，不截正文或审查证据。可缩小页数、用 chapter-read 分段读原文，或明确扩大该次预算。cache-put 可保存不超过200000字节的数据，但 cache-get 读取大缓存仍可能超默认预算，须另行增大读取预算。

history-state 从快照及后续记录还原所选出版 revision 的卡片状态；它不是按故事时间查询，也不代表工具已重新理解旧章剧情。知识倒叙仍使用 world 的故事时间证据。

```text
python "<tool>" history-update --book "<书目录>" --branch "分支ID" --input "<候选更新.json>" --expect R
python "<tool>" history-inspect --book "<书目录>" --branch "分支ID"
```

候选输入用 chapters 数组保存各章 text、summary、dependencies、complete；先保存候选，再按 inspection 返回的候选哈希填写每章审查。state_changes 对要求的卡片明确保留/变更/删除；world_changes 对旧证据记录逐项重绑定或撤销。上述内容齐全后，使用最新 review_template 填写整个分支的语义、最终状态和覆盖审查，再保存。修改了正文、摘要、依赖或状态补丁，旧审查指纹失效，不能只换哈希绕过复核。

撤销领域记录仅限已审查的历史分支：

```json
{"world_changes":{"retirements":[{"kind":"facts","id":"要撤回的事实ID","reason":"新稿撤回交付动作，相关后文已复核","evidence":{"kind":"chapter","chapter":1,"sha256":"候选正文完整SHA256","quote":"支持本次替代处理的真实新稿原句"}}]}}
```

仍引用被撤事实的认知/规则也要修复或撤销。发布会在同一事务更换正文、使旧来源失效并应用世界修复；未处理完失效证据则整次失败，原版保持可用。

```text
python "<tool>" history-publish --book "<书目录>" --branch "分支ID" --expect R
```

确认导出完成，再更新创作断点。含 world_changes 或已由历史分支发布的最新章，也走历史分支修订，不直接 replace-last。分支因无关状态更新过期可 history-refresh 重新核对；依赖内容改变则建新分支。

## 6. 旧工程迁移与回滚

1. 停止对该书的写入，保留整个书目录的独立副本；已有 WAL 可能含最新提交，不能在写入中只复制 state.sqlite3。
2. 在副本运行 `migrate --book "<副本目录>"`。schema 1 迁移会生成一致性数据库备份，回执给出 `.story/migration-backups/schema1-*.sqlite3` 路径；保存真实回执，不猜文件名。
3. 运行 `audit`、`status`、当前章 `context`，抽查旧正文、断点和来源证据。迁移建立存储结构，不替旧章补造独立审查或人物知识。
4. 回滚时停止所有书进程，在另一个独立副本使用迁移前的数据库备份及配套旧正文，配合旧版工具运行。旧备份不包含迁移后写的新章，先保全新稿，不能直接覆盖当前工作库。

容量探针和脚本测试只证明对应数据与事务路径。真实长篇还要逐步积累连续章节、整卷读稿、作者反馈和实际返工记录；不能把固定字数的合成文本称为千万字小说创作验收。

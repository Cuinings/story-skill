# 中文小说怎么用

作者直接向 Codex 说要求。Codex 负责建目录、读断点、维护计划和审稿材料，不需要作者学习 JSON 或自己计算哈希。先按 [安装与升级说明](github-release.md) 安装固定版本 v0.4.0 的完整 7 个技能；已安装 0.3.0 时保留旧版与本地修改，按原安装方式升级整套，无需重新导入书库。源码位于 `skills/`，克隆仓库后也需安装才能调用。下面的 `$story-codex` 总入口用法继续适用，任务明确时可直接使用 plan、write、analyze、review 等专用入口。[目录与分工](目录结构.md)

## 开一本长篇

```text
$story-codex 在 D:\小说\我的新书 开一本现实悬疑长篇。
第三人称限知视角，靠人的选择和实物证据推动，不要超自然。
先给核心冲突、人物关系、本卷目标和前三章细纲，不要写正文。
```

缺少可自行选择的细节，Codex 会提出并采用方案，记录在书内 `创作约定.md`。尚未授权正文时，单说“继续”会继续设计。决定开始写时明确说：

```text
$story-codex 按已定细纲开始写第1章，2200—2800字，含标点，不含标题。
完成正文、人物知识和物件状态核对，保存审稿记录和下一断点。
```

以后说“继续这本书下一章”即可。指定“连续写完前三章”时，按章闭环到第三章，不反复询问。不要把仅完成前三章称为整本小说完成。

## 写完整短篇

```text
$story-codex 在 D:\小说\新短篇 写一篇完整现实家庭故事，4000—6000字。
重点写两个都有道理的人怎样做出有代价的决定。先确定结局，再完成整篇。
不要用悬念收尾替代核心冲突的解决。
```

篇幅按所选口径实测：默认可见字符含标点；也可以明确要求“只计算汉字”或“汉字、字母、数字计数，不计标点和符号”。这几种都是字符数，不能当作网站实际显示的字数。稿件文件只放标题与正文，作者说明、审稿意见另存。

## 修改与恢复

```text
$story-codex 修改这本书最新一章：压缩重复解释，保留原有对白声线、线索和停笔点。
复核上一轮已经解决的问题没有复发，保留修改前的版本。
```

如果已在编辑器改过正文，说明“以我当前的外部改稿为依据”。Codex 会读取并核对外部版本，保留备份后提交修订。某章文件缺失时先查状态；同时有外改阻断，可用安全恢复再逐项对账。[具体恢复命令](recovery.md)

较早章节的重写会影响后文，当前工具交付独立修订稿与影响清单；复核后可在新目录建立续写基线。不要直接覆盖旧章后假设后文状态已自动更新。

## 看得到的结果

每本书包含可读的创作约定、按需设定/大纲、`chapters/` 正文，以及 `.story/` 内的计划、状态和审查凭据。完成回执至少说明实际篇幅与口径、已保存路径、未解决问题和下一断点。脚本通过仅说明字数、证据位置和保存一致；是否好看仍需读正文判断。

本仓库提供两套可读原创样稿：[长篇《渡口夜账》](../examples/渡口夜账/大纲.md)、[完整短篇《留半寸》](../examples/留半寸/drafts/01.md)。它们用于验证实际流程，题材和表达不是后续小说的固定模板。

复现同一批经过审查的稿件如何进入工具，可运行：

```powershell
python -B -X utf8 scripts/chinese_acceptance.py --workdir "D:\临时\新的中文实测目录"
```

目录必须新建或为空，避免覆盖已有小说。此命令重放已审稿件，不会重新调用模型，也不代表新一轮文学评测。

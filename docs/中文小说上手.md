# 中文小说怎么用

作者直接向 Codex 说要求。Codex 负责建目录、读断点、维护计划和审稿材料，不需要作者学习 JSON 或自己计算哈希。先按 [安装与升级说明](github-release.md) 安装同版完整 7 个技能（33 个载荷文件），本页用法对应 v0.5.3；已有旧版时保留旧版与本地修改，按原安装方式升级整套，无需重新导入书库。源码位于 `skills/`，克隆仓库后也需安装才能调用。下面的 `$story-codex` 总入口用法继续适用，任务明确时可直接使用 plan、write、analyze、review 等专用入口。[目录与分工](目录结构.md)

Windows 已知导出问题尚未修复，Windows 用户继续使用 v0.4.0。以下使用 macOS 路径举例，替换成自己的实际目录。[版本变化和平台范围](releases/v0.5.3.md)

v0.5.3 已发布；固定标签、附件、安装及远端检查的实际状态见 [发布记录](github-release.md)。旧版验证和文学评估仍保留各自版本范围，不当成本版新结果。

## 从拆书开始新起一本书

准备参考作品原文与写作父目录，使用 `$story-codex` 依次推进“拆书 → 方法提炼 → 原创开书 → 大纲细纲”。拆书先核对原文范围与引文依据，分析放在独立的作品分析目录；转化时写清方法适用条件，再重新设计新书的人物、关系、矛盾、事件链与结局。参考剧情不进入新书事实。

新书确定正式或暂定书名后，建立独立书名目录，保存策划、全书总纲、具名卷纲和近期逐章细纲。每阶段留下实际路径与下一断点；本轮只授权拆书和规划时，“继续”仍推进这两个阶段，不自动开始正文。[完整可复制请求](../README.md#从拆书开始新起一本书) · [深读方法与评估范围](作品深读与评估.md)

## 开一本长篇

```text
$story-codex 在写作父目录 /Users/作者/小说 下开一本《雾港来信》现实悬疑长篇。
第三人称限知视角，靠人的选择和实物证据推动，不要超自然。
先给核心冲突、人物关系、全书从开端到结局的走向和分卷粗纲，
再给首卷卷名、本卷目标和前三章细纲，不要写正文。
```

开书先建立可见的书名目录。本例的书根是 `/Users/作者/小说/雾港来信/`，创作约定、策划、`01_大纲细纲/` 和 `.story/` 都在里面；进入写作后，正文再保存在其中的 `chapters/第X卷 卷名/第N章 章节名称.md`。没有定名时先拟暂定书名并注明；用户已经指定最终书目录或继续旧书时沿用原位置。开书完成会给出可打开的实际书目录。

这项默认书名目录规则纳入 v0.5.3，由技能先选择最终书根再初始化。CLI 的 `--title` 仍只登记书名，不会自动在 `--book` 后补一层目录；旧书已经落在父目录时，先核对已有文件，再按实际需要整理。[书根选择与兼容说明](目录结构.md#小说一书一目录状态与可见稿件分开)

缺少可自行选择的细节，Codex 会提出并采用方案，记录在书内 `创作约定.md`。尚未授权正文时，单说“继续”会继续设计。决定开始写时明确说：

```text
$story-codex 按已定细纲开始写第1章，2200—2800字，含标点，不含标题。
完成正文、人物知识和物件状态核对，保存审稿记录和下一断点。
```

以后说“继续这本书下一章”即可。指定“连续写完前三章”时，按章闭环到第三章，不反复询问。不要把仅完成前三章称为整本小说完成。

## 大纲细纲怎样保存

长篇默认从 `01_大纲细纲/全书总纲.md` 进入，再看 `第X卷 卷名/本卷大纲.md` 和本卷的 `第N章 章节名称.md`。章细纲一章一文件，场面设计放进对应章，近期逐批补充；全书和分卷先说明走向，不要求一次写完所有章细纲。已有等效目录继续沿用，短篇可以简化成一份规划。[目录示例](目录结构.md#小说一书一目录状态与可见稿件分开)

当前稿在文档头写明状态和更新时间，旧版进入 `99_历史版本/`。说“继续细纲”时更新已有入口，不再新增一串“前十章”“第十一至十六章”的并排候选稿。若整理已有文件，Codex 会先备份、核对各版内容与引用；“候选”仍保留候选状态，未确定的分歧不会被整理动作自动定案。修改已采用细纲时，同步工具中的章计划；续写前再核对本章当前细纲与计划，已有采用依据不重复确认。工具不会自动读取大纲文件。

## 写完整短篇

```text
$story-codex 在 /Users/作者/小说/新短篇 写一篇完整现实家庭故事，4000—6000字。
重点写两个都有道理的人怎样做出有代价的决定。先确定结局，再完成整篇。
不要用悬念收尾替代核心冲突的解决。
```

篇幅按所选口径实测：默认可见字符含标点；也可以明确要求“只计算汉字”或“汉字、字母、数字计数，不计标点和符号”。这几种都是字符数，不能当作网站实际显示的字数。稿件文件只放标题与正文，作者说明、审稿意见另存。

## 修改与恢复

```text
$story-codex 修改这本书最新一章：压缩重复解释，保留原有对白声线、线索和停笔点。
复核上一轮已经解决的问题没有复发，保留修改前的版本。
```

如果已在编辑器改过正文，说明“以我当前的外部改稿为依据”。Codex 会读取并核对外部版本，保留备份后提交修订。某章文件缺失时先查状态；同时有外改阻断，可用安全恢复再逐项对账。[具体恢复命令](recovery.md)

较早章节的重写会进入历史修订分支；最新章产生的状态卡在提交后又有更新时，也进入此流程。它保留原版，并列出受影响的后文与状态。Codex 逐项完成候选稿、依赖和证据复核后，再一起发布修订、恢复导出并更新断点；复核未完成时原版继续有效。不要直接覆盖旧章后假设后文状态已自动更新。

## 深读已有作品

```text
$story-codex-analyze 完整深读 /Users/作者/小说/参考作品.txt，
把分析保存在 /Users/作者/小说/作品分析。
解释人物选择、叙述安排与情绪变化如何起作用，核心判断核对前后文和可能反例，
区分原文事实与解释，给出有适用条件的创作方法。
```

短评可以只问开篇或某一场景，不会自动扩大成全书分析。完整深读会保存来源、逐块证据和报告；遇中断后说“继续这份分析”，Codex 先找现有来源与未完成块，不重复导入。网页只有预览时，报告会说明可见范围；所有已导入块完成也不能单独证明全书无缺章。

修改已经写好的分析时仍用分析入口：

```text
$story-codex-analyze 复核这份分析的人物动机和结尾判断，回读相关原文，
保留原稿，另存完整修订稿，并留下未完成问题和下一步。
```

未定稿的逐块记录可以修正后继续聚合；已经定稿的报告另存修订稿，不覆盖原定稿。只有外部点评文档时直接修改文档，不必建书库。跨轮恢复会读取修订稿旁的进度并核对文件变化；书库里旧报告的路径不代表修订稿已完成。实际示例与评估边界见 [作品深读与评估](作品深读与评估.md)，具体恢复见 [分析稿修订与续跑](recovery.md#分析稿修订与续跑)。

## 看得到的结果

每本书包含可读的创作约定、按需设定/大纲、分卷正文，以及 `.story/` 内的计划、状态和审查凭据。新章固定保存为 `chapters/第X卷 卷名/第N章 章节名称.md`，例如 `chapters/第一卷 雨夜/第1章 雨中来客.md`；短篇与单卷作品也有明确卷名。Codex 从已定规划补齐卷名和章名，已有旧章路径继续保留。完成回执至少说明实际篇幅与口径、已保存路径、未解决问题和下一断点。脚本通过仅说明字数、证据位置和保存一致；是否好看仍需读正文判断。

本仓库提供两套可读原创样稿：[长篇《渡口夜账》](../examples/渡口夜账/大纲.md)、[完整短篇《留半寸》](../examples/留半寸/drafts/01.md)。它们用于验证实际流程，题材和表达不是后续小说的固定模板。

复现同一批经过审查的稿件如何进入工具，可运行：

```bash
python3 -B -X utf8 scripts/chinese_acceptance.py --workdir "/tmp/新的中文实测目录"
```

目录必须新建或为空，避免覆盖已有小说。此命令重放已审稿件，不会重新调用模型，也不代表新一轮文学评测。

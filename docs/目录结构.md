# 技能源码、安装副本与小说目录

v0.5.0 沿用 7 个技能入口，正文按带卷名的目录和带章名的文件保存，并保留旧章路径兼容。七入口拆分和源码从 `.agents/skills/` 移到仓库 `skills/` 始于 v0.4.0；历史 v0.3.0 保留旧结构和固定下载链接。本页对应 v0.5.0，安装与升级使用 [固定版本说明](github-release.md)，发布状态见 [Release](https://github.com/NingCui29/story-skill/releases/tag/v0.5.0)。

## 三个层次各放什么

| 层次 | 路径示例 | 保存的内容 | 不放什么 |
|---|---|---|---|
| 技能源码 | `D:/Developer/WorkSpace/story-skill/skills/` | 技能入口、流程、共享运行时代码 | 某本小说的正文、状态、私有素材 |
| 项目安装副本 | `D:/小说/写作项目/.agents/skills/` | 从同一版本复制的 7 个技能目录 | 本书的设定、大纲与章稿 |
| 用户级安装副本 | 本机安装器默认 `$CODEX_HOME/skills/`，未设置时为 `~/.codex/skills/` | 用户范围安装的技能，其他环境核对实际安装目录 | 源码维护改动和小说稿件 |
| 一本书 | `D:/小说/写作项目/新书/` | 创作约定、设定、正文和恢复状态 | 技能源码、其他书的状态 |

项目根和书根可以相同，也可以让一个写作项目包含多本书。每次操作都显式指定目标书目录；技能安装父目录不决定本次写哪本书。

## 仓库：按功能分配技能

```text
story-skill/
├── skills/
│   ├── story-codex/
│   │   ├── SKILL.md                  # 总入口、任务路由、共同约束
│   │   ├── agents/openai.yaml        # Codex 发现元数据
│   │   ├── references/
│   │   │   └── project-state.md      # 共享卡片与章节计划
│   │   ├── scripts/
│   │   │   ├── story.py             # 唯一 CLI 入口
│   │   │   ├── story_storage.py     # 存储与恢复能力
│   │   │   ├── story_search.py      # 检索能力
│   │   │   ├── story_world.py       # 结构化世界状态
│   │   │   └── story_history.py     # 历史修订分支
│   │   └── LICENSE
│   ├── story-codex-plan/            # 开书、设定、大纲、导入基线
│   ├── story-codex-write/           # 正文与续写
│   │   └── references/
│   │       ├── chapter.md          # 单章写作、审查与提交
│   │       ├── drama.md            # 中文冲突、看点、对白与场景
│   │       └── long-form.md        # 多线连载与世界状态
│   ├── story-codex-analyze/         # 拆文与分析证据
│   ├── story-codex-review/          # 审稿与修订
│   │   └── references/history.md   # 历史分支、迁移与恢复
│   ├── story-codex-research/        # 扫榜与资料查证
│   └── story-codex-cover/           # 封面
├── scripts/                        # 开发、安装、探针、打包、同步
├── tests/                          # 软件测试与回归检查
├── examples/                       # 可公开的验证样例
├── docs/                           # 使用说明与工程文档
├── benchmarks/                     # 统计配置与证据报告
├── dist/                           # 本地构建产物，Git 忽略
└── .agents/skills/                 # 本仓库试用的安装副本，Git 忽略
```

所有 7 个技能都有自己的 `SKILL.md`、`agents/openai.yaml` 和 `LICENSE`，上图省略了重复项。`SKILL.md` 说明何时使用及下一步读取什么；`references/` 仅在需要时读取，不要求每次加载全部内容；`agents/openai.yaml` 是发现元数据，不是另外一组执行代理。

核心 `scripts/` 的 5 个 Python 文件必须一起保留。`story.py` 会从同目录加载其余模块，不把某个模块单独搬入其他技能。专用技能不复制运行时，也不另建一套书库。

| 技能 | 输入与工作边界 | 主要结果 |
|---|---|---|
| `story-codex` | 不确定入口、通用约束、断点与状态定位 | 路由到所需流程，提供共享工具 |
| `story-codex-plan` | 新书规划、设定、分卷、细纲、已有小说接入 | 创作约定、近期计划和有证据的导入基线 |
| `story-codex-write` | 已授权的长短篇正文与续写 | 章稿、审查记录、状态变化及下一断点 |
| `story-codex-analyze` | 明确来源与范围的参考小说 | 可恢复分析、引文证据和汇总报告 |
| `story-codex-review` | 指定正文与修改要求 | 问题清单、最小修改、外部改稿对账或历史候选 |
| `story-codex-research` | 当前创作决策需要的榜单或事实 | 带来源、日期与限制的研究结果 |
| `story-codex-cover` | 书名、署名、题材与上传要求 | 封面方案及可用图片工具生成的实际产物 |

例如，先用 plan 做分卷与前三章细纲，授权正文后转 write；只审不改用 review；学习参考书用 analyze。切换技能只改变当前流程，同一本书的事实和断点仍保存在同一书目录。

## 安装：七个目录保持同级

```text
D:/小说/写作项目/
└── .agents/
    └── skills/
        ├── story-codex/
        ├── story-codex-plan/
        ├── story-codex-write/
        ├── story-codex-analyze/
        ├── story-codex-review/
        ├── story-codex-research/
        └── story-codex-cover/
```

6 个专用技能通过同级 `story-codex` 找到共同约束和运行时。因此安装时保留目录名和相对关系；不要将专用技能放进核心内部，也不要把核心放到另一个安装父目录。

从 v0.5.0 源码仓库安装：

```powershell
python -B -X utf8 scripts/install.py --project "D:\小说\写作项目"
```

克隆仓库后也要执行这一步；源码目录 `skills/` 与 Codex 项目发现目录 `.agents/skills/` 已分开。想在仓库内调试，目标使用 `--project "."`，再按同一安装器更新副本。

仅缺核心时，从相同版本补装 `skills/story-codex` 到已有 6 个技能所在的父目录。多项缺失或版本不一致时按 [安装与升级说明](github-release.md) 核对整套。官方安装器拒绝覆盖已有同名目录；项目安装器的 `--update` 则要求原安装带有其托管清单且没有本地改动。改用另一种安装方式时，把旧版和本地修改备份到技能扫描目录之外，再核对新安装。

## 小说：一书一目录，状态与可见稿件分开

```text
D:/小说/写作项目/
├── .agents/skills/                 # 一份套件服务该项目
├── 长篇甲/                         # --book 指向这里
│   ├── 创作约定.md                # 本书范围、风格、授权阶段和下一动作
│   ├── 设定.md                    # 按需保存的作者资料
│   ├── 大纲.md                    # 按需保存的规划
│   ├── chapters/
│   │   ├── 第一卷 雨夜/
│   │   │   ├── 第1章 雨中来客.md  # 可阅读的正文导出
│   │   │   └── 第2章 一封旧信.md
│   │   └── 第二卷 归途/
│   │       └── 第3章 再过渡口.md
│   └── .story/
│       ├── state.sqlite3          # 正文、计划、状态、事件与审查记录
│       └── drafts/                # 草稿及本次提交所需材料
├── 短篇乙/                         # 另一书根，独立状态
└── 拆文/
    └── 样本/                      # 独立分析根，不混入原创书的事实卡
```

这里只展示主要目录；工具会按操作创建来源快照、分析导出和恢复备份等材料。设定与大纲按需求建立，不为凑目录生成空文件。资料研究和封面产物保存在本次指定的书目录内，使用能说明内容的名称。

正文在 `chapters/` 下按分卷建目录，卷目录名固定为 `第X卷 卷名`，例如 `第一卷 雨夜`、`第二卷 归途`，卷序号与卷名之间一个空格。短篇与单卷作品也须明确首卷名称。每章文件名固定为 `第N章 章节名称.md`，N 是不补零的阿拉伯章号，章号与章名之间一个空格。

章计划 `volume_dir` 指定完整分卷目录名，显式填写时优先使用；未填写但计划已有 `volume` 时，可沿用该 ID 已保存且带卷名的目录，或采用已符合 `第X卷 卷名` 格式的世界卷记录标题，工具会保存本次选择；同一个 `volume` ID 已绑定的目录不能被后续单章计划静默覆盖，填写冲突目录会被拒绝。缺少完整卷名时先核对已有分卷规划；尚未命名时，依据已授权的本卷内容拟定卷名后再提交，不用仅有卷号或内部 ID 的目录代替卷名。`title` 指定章节名称，未填写时从草稿首行 Markdown H1 提取并去掉原章号前缀。新写章须提供章名，无标题的导入基线可用章名 `正文`，但仍须明确所属卷名：`adopt --volume-dir "第一卷 雨夜"` 可直接指定（替换为本书实际卷名），也可从已保存的该章计划取得完整目录；仅指定导入卷名无需新建章计划。结构化计划的 `volume` 仍是世界状态稳定 ID，展示目录用 `volume_dir` 指定。

新章节采用此布局；已有工程的旧正文路径仍可识别，更新技能不会批量重命名或移动旧稿。实际文件位置以提交、导出或对账回执为准；历史分支可用 `history-inspect` 的分页 `affected[].path` 查当前正文路径，不根据章号拼接旧式数字文件名。

`chapters/` 用于阅读和交付，`.story/` 保证状态与恢复。只复制 `chapters/` 可以交付正文，不能当作完整书籍备份。备份时等待工具退出，再复制整本书目录；直接改过导出正文，下一次先对账，不能让旧数据库静默覆盖新稿。[恢复指南](recovery.md)

不要在技能目录存放小说正文，也不要把多本书共用成一个 `.story/state.sqlite3`。运行核心 CLI 时始终明确 `--book`，例如：

```powershell
python "D:\小说\写作项目\.agents\skills\story-codex\scripts\story.py" status --book "D:\小说\写作项目\长篇甲"
```

## 改动与发布的落点

修改技能行为或说明到仓库 `skills/`；修改安装、打包和验收工具到仓库根 `scripts/`；修改某本书到该书目录。技能更新不会自动导入、迁移或重写书稿。

根 `.agents/skills/` 的安装副本和 `dist/` 构建产物不提交 Git；可公开的样例、稿件交付、文档与 benchmark 不因为这次目录整理而被整体忽略。v0.3.0 的固定 tag、附件和历史报告保留旧事实，新版以新布局重新验证后再发布。

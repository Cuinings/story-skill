# 开书与规划

先按需读取 `../story-codex/SKILL.md` 的“共同约束”；同版内容已在当前上下文中则复用。此入口已完成任务选择，不执行公共入口的路由。共享工具位于 `../story-codex/scripts/story.py`，记其绝对路径为 `<tool>`；下文所有书籍命令都显式附加 `--book "<书目录绝对路径>"`。公共技能或所需工具缺失时，说明缺失路径并提示安装完整 Story Codex 套件；不假称已执行。

从用户要求/已有项目确认题材、读者期待、主角欲望、代价、篇幅和不可改变的事实。缺少可自行选择的设定时提出并采用合理方案；涉及已有剧情的未知项先查证。不要求必须有对标书。

设计主线矛盾、开篇看点或修整平淡大纲时，读取 [冲突与看点](../story-codex-write/references/drama.md)。先确定人物难以兼得的目标、有效阻力与可兑现的阅读期待，再展开设定；不要把世界观清单当情节。近期细纲写清具体尝试、阻力如何回应、选择造成的变化，以及读者会在哪场戏得到回报，不靠“强冲突、大反转、爽点”标签代替内容。关系、幽默和日常也可承担看点。

新书：`init --book "<目录>" --title "<书名>" --kind long|short`。按需创建 `设定.md`、`大纲.md`，只展开接下来会写的章节；短篇先有结局与关键选择，长篇交代本卷目标、升级代价、终局储备。只做大纲时到此停止。

用简短 `创作约定.md` 保存题材/读者期待、叙述视角、核心欲望与代价、篇幅口径、必须保留/禁止项、当前授权阶段和下一动作；它是本书约定，不是用户画像。已有书合并新要求，遇冲突指出具体项。只为本次有意义的约束建 `kind: contract, critical: true` 卡，不复制整份设计。每次真正保存完成后更新断点；新会话先查约定与 status，尚未导出不能记成完成。

既有 oh-story 或其他项目：原目录只读，选独立新目录运行 init。读取末章、当前细纲、相关角色与未回收伏笔，以 `notes` 建立紧凑基线，再 `adopt --chapter N --draft "<最后完整章>" --summary "<衔接摘要>" --expect R`，R 取最新 status。工具只保存有证据的第 N 章快照，不假造前 N 章的审查或分析记录；原文件、原进度、原 hooks 都不改。没有必要先全量拆书。

需要保存状态卡或章计划时读取 [项目状态](../story-codex/references/project-state.md)。只做规划到已授权设计产物完成为止；用户明确要求正文后再切换 [正文写作](../story-codex-write/SKILL.md)，不把完成大纲视作自动授权正文。

# 开书与写作

## 开始

从用户要求/已有项目确认题材、读者期待、主角欲望、代价、篇幅和不可改变的事实。缺少可自行选择的设定时提出并采用合理方案；涉及已有剧情的未知项先查证。不要求必须有对标书。

新书：`init --book "<目录>" --title "<书名>" --kind long|short`。按需创建 `设定.md`、`大纲.md`，只展开接下来会写的章节；短篇先有结局与关键选择，长篇交代本卷目标、升级代价、终局储备。只做大纲时到此停止。

用简短 `创作约定.md` 保存题材/读者期待、叙述视角、核心欲望与代价、篇幅口径、必须保留/禁止项、当前授权阶段和下一动作；它是本书约定，不是用户画像。已有书合并新要求，遇冲突指出具体项。只为本次有意义的约束建 `kind: contract, critical: true` 卡，不复制整份设计。每次真正保存完成后更新断点；新会话先查约定与 status，尚未导出不能记成完成。

既有 oh-story 或其他项目：原目录只读，选独立新目录运行 init。读取末章、当前细纲、相关角色与未回收伏笔，以 `notes` 建立紧凑基线，再 `adopt --chapter N --draft "<最后完整章>" --summary "<衔接摘要>" --expect R`，R 取最新 status。工具只保存有证据的第 N 章快照，不假造前 N 章的审查或分析记录；原文件、原进度、原 hooks 都不改。没有必要先全量拆书。

## 状态与细纲

`template notes` 展示卡片结构。每张卡保存一个会影响后续的事实/人物状态/承诺，短而具体，带来源。全书硬限制、时间锚、能力上限用 `critical: true`；伏笔用 `kind: hook` 与 `due`；人物/地点设稳定 id 和 tags。作者习惯只有用户明确要求记住时才保存为 preference，不自动积累画像。

`notes --input "<卡片.json>" --expect R` 更新卡片，R 取 status。不要把整份大纲拆成无用卡片。既有卡片变更需要来源说明。

人物卡只存会影响下一步的已知/误信/未知及获知依据；作者掌握的谜底不等于人物知道。时间地点、物件归属、伤势、关系变化另用短事实卡；承诺写明触发条件或到期章。章末更新变化项，续写前核对这些状态和上章具体后果；有冲突定点补读，不把全书重新装入上下文。

`template plan` 展示计划结构；用 `plan --chapter N --input "<计划.json>" --expect R` 保存。保留用户原始要求在 `constraints`；填写目标、人物选择导致的场景变化、停笔点、字数范围、`requires`（所有涉及的角色/规则/伏笔 id）及 tags。不要以“每场几个事件”“对白百分比”代替戏剧功能。未知事实不写成已确定设定。

## 写一章 / 一段短篇

1. `context --book "<目录>" --chapter N --budget-bytes 16000`。它完整保留本章计划、critical 卡、requires 卡、到期承诺和上章摘要/末尾。预算是 UTF-8 字节，不是假称的模型 token；仅不相关的可选卡可被省略。过期/已完成伏笔也可按 requires 显式召回。查历史原因用 `recall --query "<人名或线索>"`，必要时读取精确原文。
2. 在 `.story/drafts/` 写草稿。让场景改变风险、信息、资源、关系或决定；关键转折由可理解的选择和代价产生。兑现本章承诺，避免把角色失智当阻力、把终局底牌提前用尽。反转须有先前线索和另一种可成立的解释。衔接不足就补读必要原文，不靠摘要猜。
3. 按人物和情境写声线。情绪可以直写，也可由行动承载；不强迫每句话加身体反应，不机械禁止省略号/短句/比喻。去掉重复解释、模板式升华和只有修辞没有新增内容的段落。保留有功能的安静场景、犹豫与留白。
4. `lint --chapter N --draft "<草稿>"` 核对长度、损坏字符和重复段落。`plan.length` 指定范围，`count_method` 默认 `visible_nonspace_v1`（含标点的可见字符）；`letters_numbers_v1` 只计 Unicode 字母与数字，中文/英文均逐字符；`han_v1` 只计 Unicode 已命名汉字及〇。默认排除首行 Markdown H1 标题、空白及控制/格式字符；`count_title: true` 计入标题文字但不计 H1 标记。导语算正文，正文文件不混入作者说明或审稿意见。报告所选口径及实测数，不能冒称平台后台字数。欠字补足已授权场景过程，超字压缩冗余，不增造新剧情凑数。
5. `prepare --chapter N --draft "<草稿>"` 返回 lint 及绑定当前书籍、状态版本、稿件哈希的 delta 骨架；把其中 `delta` 另存文件，由 Codex 填写摘要、changes 和因果/连续性/用户约束/文风四项观察与原句，并处理问题清单。骨架含待审阻断项，不能直接提交；工具不代替审稿。changes 仅记正文实际发生的变化，引文必须在草稿中；`blocker` 未解决不能提交，普通建议可注明取舍。
6. `commit --chapter N --draft "<草稿>" --input "<delta.json>"`。正文、审查凭据、增量状态在同一 SQLite 事务中保存；随后导出 `chapters/NNNN.md`。重复同一提交不会推进两次。版本冲突先刷新上下文并复核，不能只改 revision 数字重试。导出失败运行 `export` 恢复，不能把未导出的章说成交付完成。外部改稿冲突转 [修订流程](revise.md) 的 reconcile。

短篇可整篇作为第 1 单元，也可按用户要求分单元提交；范围对应当前单元，整篇交付时另核对合并后的总长度和导语重复。整篇验收核心冲突、主角关键选择、付出代价与结局后果的联系，以及开篇阅读期待是否兑现；开放结尾可留未知，不能把首章悬念停笔当完篇。不自动把一章要求扩成全书。明确多章请求按章循环到授权范围完成。

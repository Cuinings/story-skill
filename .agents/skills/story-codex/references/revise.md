# 审查与修订

读取目标正文、用户修改要求和相关约束；只有需要解释矛盾时补读上下文。默认当前会话一次审查；不为了更高评分循环重写整章。用户要求独立代理时才按许可委派，并明确真实执行方式。

逐项判断：
- 因果：角色为何做这个选择、有哪些可见代价，反转线索是否成立。
- 连续性：知识边界、时间、位置、伤势、能力、关系与承诺是否冲突。
- 约束：用户必发生/禁止发生、停笔点、篇幅与原创边界。
- 读感：人物声线、有效留白、重复解释、模板表达，场景是否有可感知的变化。

问题记录为位置/原句、影响、证据和最小修改建议。严重度用 blocker（违反明确要求或关键矛盾）/advice（可选择的改善）；没有证据就标疑点，不做伪精确质量分或“AI 率”。

只改造成问题的段落，同时核对过渡、后续伏笔和字数。去 AI 味保留原意、语气和情节，不把情绪一律换成动作，不把长句一律切碎。人工判断有用的反复、对称和修辞可保留。

每轮合并新增要求与必须保留项，保留上一轮问题的解决状态；重点复核旧问题是否复发、人物知识与伏笔是否仍成立。用户允许改变剧情时先同步当前章 plan 和创作约定，再取新版 context，不能用旧停笔点阻挡已授权修改。保存每轮稿件，changes 描述相对章前基线的完整最终增量；不能只写相对上一轮的差异，否则被撤回的旧事实会丢失。

工具托管的新稿先改 `.story/drafts/` 副本，使用 `prepare --chapter N --draft "<草稿>"` 的 delta 骨架填写四项带引文的审查、摘要和完整状态 changes。最近一章用 `commit --replace-last`，原版正文和增量留在 events；卡片描述修订后的状态。

若用户已在 `chapters/NNNN.md` 改稿，最新原生章先 `reconcile --chapter N` 取得修订上下文和 `external_edit`，读取该路径并另存草稿。用 `prepare --reconcile --chapter N --draft "<草稿>"` 生成带 `external_sha256` 的骨架，核对外部版本仍与已读一致后审查；执行 `reconcile --chapter N --draft "<草稿>" --input "<delta.json>"`。外部稿再变则重新读取和审查；不要只更新哈希跳过复核。其余文件缺失或待导出且有外改阻断时先 `export --safe-only`，按回执处理剩余路径；它只恢复安全路径，不代表外改已审查。导出保留被替换版本于 `.story/export-backups/`，失败查看回执，不手改数据库。

更早章节的修改先交付独立修订稿及受影响的后文章目；当前运行时不自动回放重建后文状态。若用户要把整段历史修订正式作为新基线，在独立目录用 write.md 的 adopt 流程导入修订后最后完整章和经复核的卡片。不要绕过版本检查直接覆盖旧章或 SQLite。普通未托管文件按用户授权直接修改并保留可审查的 diff。

交付包括修改文件、消除的问题、仍需取舍的建议与校验结果。“已过脚本”不等于“已过独立审稿”。

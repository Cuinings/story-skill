# 完整真实短篇：第二轮作品分析试用

本轮使用 [来源目录](sources/README.md) 中两篇真实作品的固定页面版本：《孔乙己》和《命命鸟》。保留原文异体字、段落与来源处理说明，完整性只针对已核对的单篇页面正文，不扩展为全集、校勘定本或训练数据未见样本。

## 比较与冻结

比较上一轮 v0.5.1 开发快照与同一开发版的一处最小修订：分析动作重复、缺席或变化时，先核对行动用途和发生条件是否可比。修订依据来自上一轮合成样本评阅；新作品不提供标准答案。两个快照的精确字节和生成设置在运行前冻结，按哈希区分，不把同为 0.5.1 的标识当作相同指令。

每篇每个快照各运行一次，共四份报告。生成者使用独立的新代理上下文，仅收到自己的技能副本、原文和相同任务；不读另一份回答、评论资料或评阅协议。使用宿主继承的相同设置，不伪造平台未暴露的型号、推理档和用量。随机种子在生成前固定为 20260911；两名独立代理在完成各自判断前看不到版本映射。

这是完整短篇的真实 CLI 流程试用：初始化独立分析目录，以 1,600 字符上限切块，逐块保存精确引文和解释，按需回读原文，最终综合并保存报告。最终稿要求正文 1,200—1,800 字，按去标题、去空白字符计，包含标点和引文；过程记录、工具自动来源头和逐块笔记不计入报告字数。另记录汉字数量。范围只限给定正文，不引入作者生平、后世评论或未给出的史实。

## 评阅协议

评阅者只收到原文、任务与匿名最终稿；先各自核对再进行配对判断。程序另核对覆盖、引文、回读记录和断点恢复，不能把这些程序检查视为文学判断。评阅分为五个维度，每项记录“充分／可用但有缺口／明显不足／不适用”及具体原句、原文位置和理由：

| 维度 | 判断依据 |
| --- | --- |
| 证据支持 | 引文是否准确，是否足以支持判断；人物说法、叙述者判断与分析推断是否分清。 |
| 机制解释 | 是否说明具体叙述或语言选择怎样影响理解，能否交代成立条件与代价。 |
| 全篇一致 | 核心判断是否兼容相关前后文，是否识别解释边界，是否有局部正确却全篇失真的情况。 |
| 多义与文类 | 是否比较有依据的不同读法，依作品建立的期待评价，而非强行补背景或套唯一结论。 |
| 迁移价值 | 是否提出能脱离原作人物事件的具体操作，交代情境与失败风险；不以新例数量计分。 |

错引、拼接成连续引文、人物/动作/时间归属错误、补造背景和范围夸大单列。疑似问题标记待复核，合理的不同读法不算硬错误。保留两位评阅者的分歧，不相加成总分，也不把配对偏好说成“大师级”认证。长稿、术语和谨慎措辞数量都不能自动代表深度。

全部原始回答均保留，不挑选最好的一次。基础设施失败可纠正后重试，但保留失败原因和次数；语义表现不佳不重跑挑优。评阅后如再改指令，则作为下一轮，不能沿用本轮结果证明新字节的表现。

## 证据边界

两篇名作可能已存在于模型训练材料，完整阅读记录不能证明模型完全没有借助既有知识。主代理在取得来源时看过部分原文，这也不是严格的未见留出实验。只有两个作品、一次运行与模型评阅，无法估计重复生成波动，不能代表人类编辑认可、真实长篇分析或普遍质量提高。

原文的来源、原作公有领域说明和网页授权边界见来源目录。运行产物另存于 `benchmarks/results/analysis-real/`，本目录只维护材料、任务与协议。

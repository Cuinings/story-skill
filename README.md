# Story Codex

**用自然语言规划、写作和分析中文小说。**

Story Codex 是面向 Codex 的中文小说技能套件，覆盖开书策划、大纲细纲、逐章续写、作品深读、审稿修改、资料调研和封面。你决定作品方向与本轮任务，Codex 维护文件、人物状态和进度，让后续工作能接着已有内容继续。

[安装指引](INSTALL.md) · [使用指南](docs/中文小说上手.md) · [完整文档](docs/README.md) · [v0.5.4 发布进度](docs/github-release.md#v054-发布验证记录)

**v0.5.4 正在准备发布**，补充阅读承诺与情节安排的核对、正文详略选择和跨章审稿；完整套件为 7 个技能、33 个文件，沿用独立书名目录。运行时需要 Python 3.10+，使用标准库；联网调研和封面生成使用 Codex 环境中可用的工具。[本版变化](docs/releases/v0.5.4.md)

## 安装与升级

在 Codex 对话框发送：

```text
$skill-installer 按 https://github.com/NingCui29/story-skill/blob/main/INSTALL.md 安装或升级 Story Codex
```

Codex 会核对完整套件与已有安装，保留旧版和本地修改，再完成安装验证。需要安装到某个写作项目时，在请求末尾写明项目路径。安装完成后，下一条消息即可点名使用技能；未显示时重启 Codex。

| 平台 | 安装版本 |
|---|---|
| macOS／Linux | 目标 v0.5.4，发布与下载核验完成后安装 |
| Windows | 暂用 v0.4.0；新版正文和报告导出仍存在 WinError 32 |

已用新版处理的书先完整备份，不直接降级。升级技能不会自动搬动小说文件或重新导入书库。手动安装、备份位置和升级方式见 [INSTALL.md](INSTALL.md)。

请整套安装：6 个专用技能依赖同级的 `story-codex`。只克隆仓库、下载一份 `SKILL.md` 或安装 npm 包，都不等于已完成 Codex 技能安装。

## 从拆书开始，新起一本书

用 `$story-codex` 串起 **拆书 → 提炼方法 → 原创开书 → 大纲细纲**。如果已有原创构想，也可以直接从下节开书。

| 阶段 | 完成什么 |
|---|---|
| 拆参考作品 | 核对原文范围，结合证据解释人物选择、冲突升级、信息安排、情绪与伏笔兑现 |
| 提炼写作方法 | 写清可迁移的方法、适用条件和失效风险，形成“参考方法与原创重建”文档 |
| 设计原创新书 | 根据新书定位重建人物、关系、核心机制、事件链和结局；参考剧情不作为新书事实 |
| 保存大纲细纲 | 先创建独立书名目录，再保存创作约定、开书策划、全书总纲、具名卷纲与近期逐章细纲 |

替换下面的路径和定位后，直接发送：

```text
$story-codex 我想从拆书开始，创作一本新的中文长篇。
参考作品：<原文文件绝对路径>
写作父目录：<新书保存位置>
新书定位：<题材、目标读者、预计篇幅；未确定的注明待定>

请按顺序推进：
1. 核对参考作品的完整性，将拆书结果保存在写作父目录下独立的
   “作品分析/参考书名”目录。核心判断引用原文并核对反例，原文不全时说明范围。
2. 提炼可用于原创的写作方法、适用条件与风险，形成“参考方法与原创重建”文档。
3. 根据新书定位设计原创人物、关系、核心机制、事件链和结局，
   不沿用参考作品的独特剧情；该方法文档作为新书策划资料保存。
4. 确定书名；未定时先拟暂定书名，在写作父目录下建立独立书名文件夹。
5. 在新书目录内保存创作约定、开书策划、人物与世界设定、全书总纲、
   分卷粗纲、首卷大纲和前三章完整细纲。卷目录带卷名，章细纲一章一文件。
6. 保存实际进度、文件路径和下一步；中断后从已有断点继续。

本轮只完成拆书和原创规划，不写正文。
```

参考分析与新书分别保存。书名尚未确定时，方法文档先留在独立分析目录；新书目录建立后再保存作为策划依据，并保留来源。没有完整原文时，只对取得的范围作判断。只说“继续”仍沿用本轮规划授权；决定开始正文时，使用下节的写作请求。[详细用法](docs/中文小说上手.md) · [深读方法](docs/作品深读与评估.md)

## 从开书到续写

以下路径是示例，请替换成自己的实际位置。首次开书明确给出**包含书名的完整目录**。

### 1. 先做规划

```text
$story-codex-plan 开一本现实悬疑长篇《雾港来信》。
书目录为 /Users/作者/小说/雾港来信，请先建立这个目录。
保存创作约定、人物与核心设定、全书走向和分卷粗纲，
再完成首卷卷名、本卷大纲和前三章细纲，不要写正文。
完成后告诉我书目录及已保存文件的位置。
```

题材、视角、篇幅和必须保留的要求会写入本书的 `创作约定.md`。全书先确定主线与结局方向，再逐步细化近期章节。只要求规划时，“继续”仍然继续规划。

v0.5.3 的开书流程先确认最终书目录：只给写作父目录时，默认新建书名子目录；已有作品或用户明确指定的书目录继续沿用原位置。完成后核对实际目录并交付路径，上例也明确写出了最终书根。

### 2. 明确开始写正文

```text
$story-codex-write 按 /Users/作者/小说/雾港来信 的已采用细纲写第1章。
先核对创作约定、章计划和人物状态。正文2200—2800字，含标点、不计标题。
完成审查、保存正文和状态，留下下一步，再停止。
```

后续可以说“继续这本书下一章”，也可以明确要求“连续写完前三章”。每章按计划起草、审查并保存；人物知道什么、物件归谁、哪些伏笔尚未回收，都随章节维护。

### 3. 审稿或接续中断

```text
$story-codex-review 审查 /Users/作者/小说/雾港来信 的第1章，
核对人物认知、因果、对白和重复解释，先列问题与修改建议，不直接重写。
```

换会话或处理中断后，说明书目录和要继续的工作。Codex 先读取已有约定、状态和相应文件，再接断点。已经修改过导出的正文时，说明“以当前外部改稿为依据”。具体流程见 [恢复指南](docs/recovery.md)。

## 文件放在哪里

**一书一目录，规划与正文分别保存。** 下面展示随创作逐步形成的目录；只做规划时不提前生成正文或空章。

```text
小说/
└── 雾港来信/                         # 本书目录
    ├── 创作约定.md                   # 方向、要求、授权阶段与下一步
    ├── 设定.md                       # 按需保存的策划与设定
    ├── 01_大纲细纲/
    │   ├── 全书总纲.md
    │   ├── 第一卷 迟到的信/
    │   │   ├── 本卷大纲.md
    │   │   ├── 第1章 雨中来客.md
    │   │   └── 第2章 一封旧信.md
    │   └── 99_历史版本/              # 规划旧稿
    ├── chapters/                     # 正文
    │   ├── 第一卷 迟到的信/
    │   │   ├── 第1章 雨中来客.md
    │   │   └── 第2章 一封旧信.md
    │   └── 第二卷 失声码头/
    │       └── 第3章 再过渡口.md
    └── .story/                       # 状态、草稿与恢复资料
```

- **书目录用书名。** 新书先确定实际书根，约定、策划、大纲、正文和状态都保存在其中；已有等效布局沿用。
- **卷目录带卷名。** 格式为 `第X卷 卷名`，例如 `第一卷 迟到的信`；短篇与单卷作品也有明确卷名。
- **章节独立成文件。** 格式为 `第N章 章节名称.md`，N 使用不补零的阿拉伯数字，例如 `第1章 雨中来客.md`。细纲和正文分别放在各自目录。
- **当前稿与旧稿分开。** 同一范围维护一个当前入口，旧规划归档；候选是否采用仍以实际约定为准。修改已采用细纲时，同步相应章计划。

`.story/` 是隐藏目录，但它的外层书目录应当可见。备份时等待书籍工具退出，再复制完整书目录；只复制 `chapters/` 只能带走正文。已保存章节的位置以实际回执为准，已有旧路径不会因升级自动改变。[完整目录规范](docs/目录结构.md)

## 七个技能入口

不确定选哪个时，使用 `$story-codex` 描述目标；任务明确时直接点名专用入口。

| 技能 | 用途 |
|---|---|
| `$story-codex` | 选择流程、读取共同约束、衔接当前任务 |
| `$story-codex-plan` | 开书策划、人物设定、大纲细纲、已有作品续写基线 |
| `$story-codex-write` | 长短篇正文、逐章续写、状态衔接 |
| `$story-codex-analyze` | 开篇点评、全书深读、分析稿修订与中断续跑 |
| `$story-codex-review` | 审稿、修改、去 AI 味、外部改稿与历史章节修订 |
| `$story-codex-research` | 榜单调研、题材研究、写作素材与事实查证 |
| `$story-codex-cover` | 封面构思、生成与修改、文字和尺寸核对 |

切换规划、写作和审稿时沿用同一本书。参考作品的分析单独保存，结论可以帮助创作，参考剧情不能成为原创书的既定事实。

例如，完整深读一部作品：

```text
$story-codex-analyze 完整深读 /Users/作者/素材/样本.txt，
分析保存到 /Users/作者/小说/作品分析/样本。
解释人物选择、因果、情绪与叙述方法，核心判断引用原文并核对反例。
已有进度就从断点继续，最后给出有证据的综合报告。
```

分析范围以实际取得的文本为准，缺章或仅有预览时会注明。分析记录、报告修订和跨章论证的用法见 [作品深读与评估](docs/作品深读与评估.md)。

## 长篇衔接与作品质量

长篇流程支持分卷、多故事线、人物认知、物件和资源状态、规则变化、远期伏笔及历史章节修订。续写前读取本章所需的计划与相关状态；缺少关键资料时先补齐。修改早期章节时，沿影响范围复核后文。[超长篇实操](docs/超长篇实操.md)

v0.5.4 在既有写作指导上补充三处实际用法：

- **规划核对阅读承诺。** 将书名、简介和题材标签与阶段情节对应，说明慢热或延后兑现的理由；按本次授权校准定位或安排。
- **正文按作用安排详略。** 需要核算和核验的内容完整核清，正文保留影响判断、选择、关系和氛围的过程；已有且无新作用的例行执行可压缩，书内明确要求展示的内容照办。
- **审稿补读必要前后文。** 为节奏、关系和兑现问题定位原文，区分回报尚未发生、体验被跳过及余波仍有作用；修订范围由实际问题和授权决定。

[三题开发比较](benchmarks/results/quality-focus-2026-09-11/README.md) 结果混合：规划持平，正文修订略偏初版候选，跨章审稿略偏旧版。最终措辞仅经过语义复核，没有重新盲评；这些结果不证明稳定的文学质量提升。程序负责文件、状态和保存检查，文学判断仍需读稿复核。[中文场景指导](skills/story-codex-write/references/drama.md) · [评估方法](docs/evaluation.md)
